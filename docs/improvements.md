# Следующие эксперименты

Результаты первого сравнения сохраняю отдельно: commit `75937c2`, [итоговые числа](test-results.json) и протокол [пунктов 5–6](fine-tuning.md). Новые эксперименты их не заменяют. МРТ, веса и таблицы отдельных исследований остаются локально.

Здесь проверяю пять предложенных продолжений:

1. Равновесный ансамбль трёх голов: один общий SpineNet и среднее трёх векторов вероятностей.
2. Небольшая нелинейная голова `512 → 64 → ReLU → Dropout(0.2) → 3`.
3. Ordinal-голова в стиле CORAL: общий скалярный признак и две упорядоченные границы между тремя категориями. Решение — argmax восстановленных вероятностей трёх классов.
4. Локальная галерея ошибок и правильных контрольных случаев для проверки с врачом.
5. Три разбиения по исследованиям и bootstrap-интервалы, которые учитывают неопределённость по случаям.

Параметры зафиксировал в [head-v2.json](../configs/head-v2.json) до запуска. Новые головы обучаю на уже сохранённых 512 признаках; SpineNet не дообучаю. Для каждого варианта использую те же три seed, одинаковые оптимизатор и правило весов классов.

Кроссвалидацию провожу только внутри прежнего train. Один `study_id` со всеми уровнями всегда относится к одной части. Лучшую эпоху выбираю внутри каждого CV-разбиения. Затем беру медиану выбранных эпох для соответствующих модели и seed, обучаю на полном прежнем train и один раз считаю прежнюю validation. Выбор варианта делаю по среднему CV macro-F1 ансамбля. CV используется для выбора, поэтому его оценку не называю независимой проверкой качества.

Прежний тест уже открыт. Новые модели на нём не выбираю и не подстраиваю; независимое подтверждение новой версии потребует следующей заранее отложенной выборки. Bootstrap старых тестовых предсказаний оценивает неопределённость уже завершённого сравнения и не меняет модели.

Галерея ошибок содержит настоящие МРТ и хранится только в `reports/runs/error-review-v2`. Отбор целевой: ошибки умеренной и тяжёлой категорий, завышение степени, L5–S1 и расхождения голов. Правильные контрольные случаи помогают врачу проверять и удачные предсказания. Врачебные поля остаются пустыми; технический просмотр не заменяет анатомическую или клиническую проверку.

Все 36 обучений завершены. Нелинейная голова MLP выбрана по CV **до** проверки прежней validation. Нового независимого теста в этом эксперименте нет.

| Линейная | 0.680 | 0.667 | 26 / 42 | 0.396 |

| Ordinal / CORAL | 0.545 | 0.519 | 29 / 42 | 0.000 |

Ансамбль прежних трёх голов на этой validation дал **0.678**, отдельные прежние головы — 0.676–0.682. Явного выигрыша от одного усреднения здесь нет. Старые головы выбирали эпоху по этой validation, новые — по CV, поэтому это историческое сравнение с разными правилами выбора эпохи.

У нового MLP-ансамбля 29 из 42 тяжёлых уровней определены верно против 26 у нового линейного ансамбля. Тяжёлый → норма/лёгкий: 5 против 8; завышений нормы/лёгкого у обоих по 27 из 504. Один тяжёлый уровень не обработан и остаётся в общем знаменателе. На L5–S1 оба ансамбля не нашли ни одного из трёх тяжёлых случаев validation.

Проверенный ordinal-вариант не предсказывает умеренную категорию. У обученных голов расстояние между границами 1.04–1.06: при выбранном argmax восстановленных вероятностей это делает умеренную категорию недостижимой. Это отрицательный результат данной параметризации и правила решения; его нельзя переносить на ordinal regression вообще. Правило после просмотра результатов не менял.

Разница validation macro-F1 MLP и нового линейного ансамбля — **+0.026**, 95% bootstrap-интервал **[-0.003; +0.061]**. Интервал включает ноль: MLP остаётся перспективным кандидатом, а не доказанно лучшим решением.

Дополнительный анализ старого теста v1 дал разницу macro-F1 новой головы и исходного SpineNet **+0.063**, интервал **[-0.015; +0.143]**. Это среднее метрик трёх отдельных голов, не ансамбль вероятностей. Разброс по исследованиям заметно больше разброса по seed. Интервалы условны на этих весах и данных; неопределённость разметки и перенос на другую клинику они не измеряют.

Для врача подготовил локальную галерею из **48 случаев**: 47 validation и 1 train, включая восемь правильных контролей и два отказа поиска уровня. Все отображённые исходные серии прошли проверку контрольных сумм и геометрии; 46 доступных ROI конечны и непусты. Я просмотрел все шесть контактных листов технически. Нумерацию, пригодность ROI и разметку врач ещё не подтверждал. Целевой отбор ошибок не позволяет оценивать по галерее частоту ошибок в популяции.

Для ordinal-диагностики: если расстояние между границами равно `d`, максимальная вероятность средней категории в этой модели равна `tanh(d/4)`. Пока `d < ln(4)`, она не может выиграть argmax. У трёх сохранённых голов `d = 1.046 / 1.037 / 1.062`, поэтому проблема объясняется конкретным обученным представлением и правилом вывода. Другое ordinal-правило решения можно проверить следующим отдельным протоколом; этот результат я сохранил без исправления после просмотра validation.

## Как повторить

После подготовки кэша первого эксперимента:

```bash
ai-spine ensemble-validation --out reports/runs/ensemble-v1-validation
ai-spine head-experiments --out reports/runs/head-v2 --protocol configs/head-v2.json --threads 4
ai-spine error-review --out reports/runs/error-review-v2 --count 48 --seed 2026 --experiments reports/runs/head-v2
ai-spine bootstrap-v1 --out reports/runs/bootstrap-v1-verified --resamples 2000 --seed 2026
ai-spine bootstrap-development --out reports/runs/bootstrap-v2-validation --resamples 2000 --seed 2026
ai-spine report-improvements
```

Обучение и сохранение отдельных запусков требуют новых выходных папок. Готовые v1/v2 не перезаписываю. Все агрегированные числа этого продолжения находятся в [improvement-results.json](improvement-results.json); веса, предсказания по отдельным исследованиям и изображения — только локально.

## Что проверить с врачом

Открываю локальный `reports/runs/error-review-v2/index.html`, рядом — `doctor_review.csv`. Страница `comparison.html` показывает предсказания новых линейных, MLP и ordinal-голов на тех же случаях; изображения и исходная врачебная форма при добавлении сравнения не меняются. Для каждого случая нужны три ответа: правильно ли назван уровень, подходит ли вырезанная область для оценки центрального канала и согласен ли врач с категорией разметки. Если категория спорная, сохраняю предложенную степень и комментарий отдельно от исходной RSNA-разметки.

В двух случаях `missing_roi` сначала стоит проверить наличие нужного отдела в поле зрения и причину отсутствия L5/S1. В остальных случаях отсутствие технического сбоя не подтверждает правильную анатомическую нумерацию. Галерея показывает разметку и предсказания, поэтому она подходит для разбора ошибок, а не для слепой независимой экспертной валидации.
