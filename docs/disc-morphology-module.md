# Подключаемый модуль морфологии дисков

Подключаю Disc Morphology CLI отдельным адаптером. Основная модель оценивает центральный стеноз на L4–L5 и L5–S1. Дополнительный модуль запускает TotalSpineSeg и SpineSegPlus, строит кандидатную маску и рассчитывает её геометрию на сагиттальных срезах.

| Поле | Значение |
| --- | --- |
| B, мм | Ширина основания на опорной линии |
| D, мм | Максимальная связная хорда наружной части, параллельная основанию |
| H, мм | Максимальное перпендикулярное расстояние от опорной линии |
| D/B | Отношение ширины наружной части к основанию |

В карточке есть выбор уровня, покадровые числа, контур, опорная линия и переход к представительному срезу. Сводка объединяет ответы центрального стеноза и морфологии для одного загруженного исследования. Для уже сохранённых серий доступна кнопка запуска модуля.

`geometric_candidate` хранит гипотезу формы, а `clinical_status` остаётся `indeterminate`, как у исходного CLI. Отсутствие маски сохраняется как неизвестный результат. В интерфейсе отмечаю непроверенное обучающее покрытие верхних трёх поясничных уровней. Покадровые числа и причины неопределённости доступны одновременно.

В полном прогоне морфологии на 18 сагиттальных срезах получил 438 вокселей кандидатной маски на L4–L5. На пяти срезах доступны D и H. На представительном срезе D составляет около 5,03 мм, H — 11,61 мм относительно предложенной опорной линии. Основание B не определилось (`missing_base`), поэтому D/B и тип формы остаются неопределёнными. Все пять записей имеют `geometry_measurable=false`. В сводке сохраняю эту неопределённость вместе с числами. Это геометрия кандидатной маски, её анатомическую правильность ещё нужно проверить.

## Подключение

Код адаптера находится в `src/ai_spine_med/analysis_modules.py`. Он вызывается после центральной модели в той же последовательной очереди. Ошибка дополнительной обработки сохраняется в `modules.disc_morphology`. Ранее полученные оценки стеноза доступны независимо.

Использую [Disc Morphology CLI](https://github.com/ndreuu/disc-morphology-cli) на commit `80d2aeff96b044aa9e0f1c585a6a0de73554c53c`. Адаптер проверяет SHA исходников CLI и commit модели SpineSegPlus. Для CLI и нейросетей нужны отдельные окружения. Пример образа лежит в `deploy/review/Dockerfile.morphology`.

Собрать оба образа из текущего кода репозитория.

```sh
docker build -t ai-spine-review:v13 -f deploy/review/Dockerfile .
docker build -t ai-spine-review:disc-v17 -f deploy/review/Dockerfile.morphology .
```

Один раз подготовить модели в записываемом томе `/disc-models` внутри этого образа.

```sh
/opt/disc-cli/bin/disc-morphology setup \
  --model-home /disc-models \
  --python /opt/disc-runtime/bin/python \
  --source /opt/disc-source
```

Подключить тот же том к контейнеру сайта и задать операторскую конфигурацию.

```sh
REVIEW_ANALYSIS_MODULES='{"disc_morphology":{"enabled":true,"python":"/opt/disc-cli/bin/python","model_home":"/disc-models","device":"cpu","threads":2,"timeout_seconds":3600}}'
```

Без этой настройки сайт показывает доступность модуля отдельно. Настройка не поступает из пользовательского архива. Пользователь передаёт полную сагиттальную T2-серию в обычном ZIP/DICOM через существующую загрузку.

Источник каждого результата сопоставляется с файлом DICOM по SHA-256. В публичный JSON попадают разрешённые численные поля и координаты в ориентации просмотрщика. Сырые JSON, DICOM UID, локальные пути и произвольные сообщения upstream остаются внутри процесса. Временные маски и HTML удаляются после обработки.

Новый результат JSON включает `modules` и `patient_summary`. Старые записи получают сводку при чтении. Повторный запуск выполняется через защищённый `POST api/uploads/{upload_id}/modules` с теми же Origin и `X-Upload-Intent`, что и обычная загрузка. Ответ — `202` и запись в очереди. Повторные задания одного исследования блокируются.

Для готового окружения есть дополнение `deploy/review/compose.morphology.yaml`. Оно подключает отдельный том весов и включает модуль. Основной `compose.yaml` позволяет запускать сайт с одним анализом стеноза.

Для обмена тензорами между процессами nnU-Net задаю контейнеру `shm_size: 512m`. В проверке одного и того же CPU-тензора на 96 МиБ лимит 64 МиБ приводил к SIGBUS, а 512 МиБ позволяли выполнить передачу. Внутренний журнал модели при ошибке сохраняется отдельно с правами `0600` и ограничением 2 МиБ.

## Ресурсы

В исходном проекте измерен пик памяти около 17 ГБ на одном полном CPU-запуске. Подготовил на mine-test отдельный runtime, проверил зависимости, SHA четырёх официальных архивов и равенство тензоров преобразованных весов.

В первой проверке через настоящий API использовал копию сохранённой серии из 18 срезов. Контейнер получил 2 ГБ RAM, 3 ГБ вместе со swap и один CPU. На занятом сервере оставалось около 225 МиБ доступной RAM и 49 МиБ swap, поэтому защита ресурсов остановила пробный контейнер. После освобождения памяти увеличил лимиты до 3500 МиБ RAM, 5 ГиБ вместе со swap и двух CPU. Отдельно исправил лимит общей памяти Docker, описанный выше.

Оба повторных запуска завершились успешно. Отдельная морфология заняла 18 минут 4 секунды. Проверка через новую загрузку прошла всю цепочку ZIP → оценка стеноза → морфология → сводка примерно за 21 минуту 16 секунд после подготовки серии. В ней морфология заняла 18 минут 8 секунд. В выборочных замерах максимум полной цепочки составил около 2,68 ГиБ физической памяти и 567 МиБ swap. Событий OOM и превышений лимитов не было.

Вероятности основной модели совпали с исходным результатом точно. Все поля нормализованной морфологии совпали в двух запусках, включая контуры, числа, выбранные срезы и флаги качества. Это проверка запуска и воспроизводимости на одной серии. Пригодность найденной маски и измерений требует отдельной врачебной оценки.

Модуль включён на сайте. Для новой загрузки оба анализа выполняются в одной очереди. Для прежних серий доступна кнопка повторного анализа морфологии. Проверочный результат опубликован в «Загрузке 001» после сверки всех 18 исходных DICOM по SHA-256.

В адаптер добавил проверку ресурсов Linux перед запуском и во время обработки. При сумме доступной RAM и свободного swap ниже 384 МиБ модуль завершает своё дерево процессов и сохраняет `resource_unavailable`. Этот контроль дополняет ограничение памяти контейнера. Оценки центрального стеноза сохраняются.
