# Эксперимент с замороженным SpineNet

Я сравниваю исходный SpineNet с новой линейной головой для трёх категорий центрального стеноза. Детектор, нумерация позвонков, извлечение областей и основная сеть остаются исходными. Это этапы 3–4 плана практики; дообучение последнего блока и финальный тест будут отдельным экспериментом.

Протокол зафиксирован до получения результатов валидации:

1. Использую уже подготовленное разбиение RSNA: 1 382 исследования для обучения, 297 для валидации, 295 для будущего теста. SHA-256 `studies.csv`: `1fc2705dc36ce97179fb1b38e08a5c7c1e3e8f8852d5cb1d82874e9f19d46004`. Сейчас тест не загружаю и не обрабатываю.
2. На каждой серии запускаю исходную локализацию SpineNet. Извлекаю только автоматически найденные L4–L5 и L5–S1. Координаты RSNA не подставляю вместо неудачной локализации. Отсутствующий уровень остаётся `not_assessed`.
3. Из каждого входа классификатора `(1, 9, 112, 224)` сохраняю 512 признаков перед последним слоем и четыре исходных CCS-logit. Основная сеть работает в `eval()` без градиентов; её веса и статистики BatchNorm не меняются.
4. Для исходного SpineNet объединяю вероятности «нет» и «лёгкий», затем выбираю максимальную из трёх вероятностей. Сначала выбрать максимум из четырёх классов и потом объединить метки — другая процедура. Сопоставление шкал SpineNet и RSNA здесь исследовательское; врач его не подтверждал.
5. Обучаю `Linear(512, 3)` на сохранённых признаках. AdamW, learning rate `0.001`, weight decay `0.0001`, batch size `64`, до 20 эпох, остановка после пяти эпох без улучшения validation macro-F1. Веса классов — обратный квадратный корень из числа доступных обучающих примеров, нормированный к среднему 1. Аугментаций на этом этапе нет.
6. Повторяю обучение с seed `42`, `2024`, `3407`. Внутри каждого запуска сохраняю эпоху с лучшим validation macro-F1; при равенстве — более раннюю. Показываю все три результата и среднее со стандартным отклонением, не выбираю удачный seed как окончательный результат.
7. Сравниваю модели на одинаковых автоматически извлечённых областях валидации. Считаю macro-F1 по фиксированным трём классам, матрицу ошибок, полноту тяжёлого стеноза и ошибки «тяжёлый → норма/лёгкий». Отдельно показываю долю обработанных уровней, в том числе по истинной категории. Необработанный тяжёлый случай входит в общий знаменатель обнаружения тяжёлого стеноза.

Области и признаки кэшируются вместе с контрольными суммами данных, исходников и весов. Повторный запуск использует совместимый кэш; изменённые входы не должны незаметно смешиваться со старым экспериментом. Время подготовки признаков и время обучения головы учитываю отдельно.

Перед запуском на MPS проверил совпадение с CPU на одной обучающей серии: нумерация, порядок областей и категории исходной модели совпали. Максимальная разница 512 признаков на одинаковых областях составила `7.15e-7`, CCS-logit — `5.72e-6`. Это техническая проверка одного примера, а не доказательство равенства результатов на любом входе.

Для технической проверки областей просмотрел 36 примеров из разных обучающих исследований: по шесть на каждое сочетание уровня и категории. Все области имеют размер `(9, 112, 224)`, содержат конечные значения и не являются пустыми. Очевидных переворотов или повреждённых изображений в этой небольшой выборке не обнаружил. Независимый пересчёт исходного классификатора по сохранённым признакам совпал с его выходами с максимальной ошибкой `9.54e-7`.

Такая проверка помогает заметить технический сбой, но не подтверждает правильность нумерации, охват канала или клиническую степень стеноза. Это ещё предстоит проверить с врачом. В открытый репозиторий попадают только агрегированные результаты и мои схемы: условия RSNA запрещают распространять изображения пациентов.

В группе `Sagittal T2/STIR` встречаются разные T2-подобные последовательности. Подтип по очищенным заголовкам надёжно не определяется. На L5–S1 всего 13 тяжёлых примеров в обучении и три в валидации, поэтому отдельную оценку этого уровня нельзя считать устойчивым подтверждением качества.

## Результат первого запуска

Полностью обработал 1 679 серий train и validation. Из 3 358 целевых уровней получил 3 320 областей: 2 732 для обучения и 588 для валидации. В 34 случаях SpineNet не нашёл нужный позвонок, ещё четыре уровня не обработались из-за неравномерного расстояния между срезами в двух обучающих сериях. На валидации все шесть пропусков связаны с локализацией; среди них один тяжёлый случай.

Macro-F1 исходного SpineNet — `0.5887`. Новая голова дала `0.6793`, `0.6760`, `0.6817`; среднее — `0.6790`, стандартное отклонение — `0.0029`. Лучшие эпохи трёх запусков — 9, 11 и 12 соответственно. Из всех 42 тяжёлых случаев валидации исходная модель правильно отнесла к тяжёлым 19, новая — 26 во всех трёх запусках. Ошибок «тяжёлый → норма/лёгкий» стало восемь вместо десяти; один тяжёлый уровень остался необработанным.

Улучшение сопровождается большим числом завышений категории у «нормы / лёгкой»: 22–27 вместо 12 на 504 обработанных областях. На L5–S1 все три тяжёлых случая остались нераспознанными и у исходной модели, и у новых голов. Общий показатель по двум уровням не заменяет этот разбор.

Это результат адаптации на валидации, по которой выбирал эпоху обучения. Изображения отложенного теста не загружал и итоговое качество на нём пока не оценивал. Все агрегированные числа сохранил в [results.json](results.json), графики — в README; веса и таблицы отдельных исследований остаются локально.
