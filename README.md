# ai-spine-med

Исследовательский проект для практики: дообучение и сравнительная оценка SpineNet при определении степени **центрального стеноза** на уровнях **L4–L5 и L5–S1**.

Сейчас реализованы запуск исходной модели и подготовка данных для последующих экспериментов. Обучения и измерения точности пока нет. **SpineNet и TotalSpineSeg — разные системы**; здесь используется [SpineNetV2](https://github.com/rwindsor1/SpineNet).

Фактически проверено: два примера авторов и три обучающие серии RSNA; подготовлен реестр 1 974 исследований с разбиением 1 382 / 297 / 295. Локально загружены три серии (54 DICOM), а не все изображения набора. Ограничения покрытия и статистика — в [отчёте проверки](docs/verification.md).

## Окружение

Python 3.11–3.12; фактическая проверка выполнена на macOS ARM64, Python 3.12, CPU. NVIDIA GPU для этих двух этапов не нужен. Подробности проверки — в [docs/verification.md](docs/verification.md).

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[data,dev]'
ai-spine doctor
```

В уже подготовленном локальном checkout `.venv` существует: достаточно `source .venv/bin/activate`.

NumPy ограничен версией 1.x, OpenCV — `<4.12`: исходный SpineNet использует API старого NumPy. Проверенные версии всех пакетов записаны в `requirements-macos-arm64-py312.lock`. Для повторения именно этого окружения перед установкой проекта можно выполнить `python -m pip install -r requirements-macos-arm64-py312.lock`; на другой платформе используйте зависимости из `pyproject.toml`.

## 1. Исходный SpineNet

```bash
ai-spine fetch-assets
ai-spine smoke --examples-root data/examples --out reports/runs/demo-01 --device cpu
```

Первая команда скачивает исходники на фиксированном commit, четыре файла весов (~822 MB) и два маленьких примера авторов. SHA-256 всех ресурсов закреплены в `src/ai_spine_med/assets.lock.json`; изменившийся файл не будет принят молча. Всё это хранится локально в `.cache/` и `data/`, вне Git.

Модель остаётся с исходными весами. В локальную копию исходников воспроизводимо вносится одна правка совместимости: `dtype=np.bool` → `dtype=bool`. Для чтения checkpoint используется ограниченный загрузчик PyTorch с узким списком разрешённых типов NumPy; небезопасный `weights_only=False` не используется.

В каталоге результата:

- `summary.json` — версии, контрольные суммы, число обработанных серий, покрытие целевых уровней и время;
- `target_levels.csv` / `.json` — исходные оценки двух уровней или `not_assessed`;
- `*_all_original_grades.csv` — все оценки исходной модели;
- `cases.json` — ход обработки и учёт отказов.

Шкала исходного SpineNet: **1 — нет стеноза, 2 — лёгкий, 3 — умеренный, 4 — тяжёлый**. На этом этапе сохраняем её как есть. Объединение первых двух классов и сопоставление шкал с RSNA проверим до сравнительного эксперимента.

Если хотя бы один целевой уровень не оценён, CLI возвращает код 1 и сохраняет полученные результаты со статусом `not_assessed` для отсутствующего уровня. Неполное покрытие нужно учитывать отдельно от качества классификации.

В примерах авторов отсутствует часть геометрии DICOM. Только для `--examples-root` применяется ровно та подстановка метаданных, которую используют авторы в quickstart. Это демонстрационные изображения без проверенных эталонных оценок; по ним нельзя считать точность или обобщать время на реальные клинические серии.

Для настоящей серии используется отдельный строгий загрузчик, без подстановки демонстрационной геометрии:

```bash
ai-spine smoke --dicom-dir data/rsna/train_images/STUDY/SERIES --out reports/runs/rsna-01
```

Он проверяет ориентацию и целостность серии, сортирует срезы по физическим координатам, применяет DICOM rescale, поддерживает встроенный RLE decoder и сохраняет физический масштаб при приведении анизотропных пикселей к изотропной сетке. Неподдерживаемый вход получает отказ, а не оценку «норма». CUDA можно выбрать явно через `--device cuda:0`; MPS не проверялся.

## 2. Данные RSNA

Используется только официальный [RSNA 2024 Lumbar Spine Degenerative Classification](https://www.kaggle.com/competitions/rsna-2024-lumbar-spine-degenerative-classification/data). Сначала нужно войти на Kaggle и самостоятельно принять правила конкурса. Для CLI настройте вход через `kaggle auth login` либо официальный локальный файл `~/.kaggle/kaggle.json`. Не помещайте токены в код или Git.

Сначала скачиваются только три небольшие таблицы:

```bash
python -m ai_spine_med.kaggle_download metadata --data-root data/rsna
python -m ai_spine_med.data --data-root data/rsna --out artifacts/rsna-v1 --seed 42
```

Ожидаемые исходные файлы: `train.csv`, `train_series_descriptions.csv`, `train_label_coordinates.csv`. Если они уже скачаны, просто положите их в `data/rsna/`. Изображения должны иметь стандартную структуру `data/rsna/train_images/<study_id>/<series_id>/<instance_number>.dcm`.

Подготовка создаёт:

| Файл | Содержание |
| --- | --- |
| `studies.csv` | Фиксированное разбиение исследований: 70% train, 15% validation, 15% test |
| `series.csv` | Сагиттальные T2/STIR-серии, пути, наличие локальных файлов, ожидающий проверки статус геометрии |
| `labels.csv` | Метки двух уровней: `0=normal_mild`, `1=moderate`, `2=severe` |
| `coordinates.csv` | Эталонные локализаторы для проверки; не автоматический источник ROI на тесте |
| `summary.json` | Распределения классов по уровням и выборкам, пропуски, исключения, SHA-256 |

Все серии и оба уровня одного `study_id` остаются в одной выборке. Разбиение воспроизводимо и стратифицировано по худшей доступной степени двух уровней. В CSV нет отдельного `patient_id`; основание для группировки по `study_id` — правило авторов не включать пациента более одного раза, описанное в [приложении к публикации LumbarDISC](https://pubs.rsna.org/doi/suppl/10.1148/ryai.250480/suppl_file/ryai250480suppa1.pdf). Для будущих данных университетов потребуется отдельная проверка повторных исследований одного пациента.

Пропущенная метка исключается, а не становится нормой. Отсутствие координаты не удаляет имеющуюся метку стеноза. Если классов мало, программа сохраняет все исследования и сообщает, что не каждый класс представлен в каждой выборке. Установленное разбиение нельзя случайно перезаписать с другим seed или составом исследований: для нового эксперимента нужен новый каталог.

**Важное уточнение к плану:** официальная группа называется `Sagittal T2/STIR`, включает несколько T2-подобных последовательностей. После очистки DICOM надёжно различить обычную T2 и STIR по заголовкам нельзя. Сейчас отбирается эта группа, а `sequence_subtype` остаётся `unknown`. Отбор только обычных T2 потребует отдельного ручного контроля. В RSNA также есть условность: L5/S1 — самый нижний полностью сформированный диск; нумерацию SpineNet нужно отдельно сверить.

После фиксации разбиения можно скачать три полные серии **только из train**, затем обновить сведения о наличии файлов:

```bash
python -m ai_spine_med.kaggle_download sample --data-root data/rsna --manifest-dir artifacts/rsna-v1 --count 3
python -m ai_spine_med.data --data-root data/rsna --out artifacts/rsna-v1 --seed 42
```

Список выбранных путей будет в `data/rsna/sample_download.json`. Текущий официальный SDK получает и кэширует списки файлов только выбранных серий через API каталогов, проверяет полноту и пагинацию; обход всего конкурса не нужен. Для старых клиентов без этого SDK-вызова предусмотрен медленный вариант с полным каталогом имён. Изображения скачиваются только для выбранных серий. Ограничения `--count` и `--max-files` защищают от случайной загрузки всего архива (~35 GB). Наличие файлов ещё не подтверждает правильную геометрию или качество изображения: это отдельная проверка следующего этапа.

Полную обучающую выборку МРТ пока не скачиваем. Для обучения нужно будет отдельно загрузить остальные серии из зафиксированного списка; команда `sample` намеренно ограничена небольшим набором для запуска.

## Проверки

```bash
python -m pytest -q
ruff check src tests
ruff format --check src tests
```

Тесты используют искусственные таблицы и DICOM, включая реальную RLE-компрессию. Они проверяют группировку, пропуски меток, воспроизводимость, защиту разбиения, пагинацию загрузчика и геометрию. Это проверки программы, не измерение медицинской точности.
